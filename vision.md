# Product vision

Spoken notes are easy to create and surprisingly hard to recover. A useful detail may be buried in yesterday's update, mixed with an older plan, or phrased differently from the way someone remembers it later. Kivi should make those moments easier to find and use again.

The product is a careful work companion. It remembers enough to restore context, keeps the original record close by, and leaves the final decision with the person using it. The main goal is continuity: helping someone return to a topic without reconstructing it from scattered notes and partial memory.

Three activities matter most. First, a person should be able to recover an earlier interaction and inspect what was actually said. Second, Kivi should help explain the current state of a topic when plans or details have changed. Third, it should prepare a grounded draft using the relevant history and writing preferences. These activities should work across ordinary work topics and across Hindi and English references to the same subject.

Useful memory includes factual claims, decisions, events, and explicit preferences about how someone wants help. Each memory should retain its source, time, speaker, and scope where those details are available. Temporary details can remain searchable without becoming permanent memories. Repetition alone should not create a personality profile, and quoted preferences should remain attached to the person who expressed them.

Kivi should handle uncertainty conservatively. A dictated message is not necessarily a sent message. A proposed deadline is not automatically an accepted deadline. A newer quotation does not always replace an earlier fact. When records conflict, dates are missing, or raw speech recognition differs from formatted text, the uncertainty should remain visible instead of being hidden behind a confident answer.

Ordinary dictation and Hey Kivi serve different purposes. Dictation should capture the intended words with the selected vocabulary and style. It should not silently add facts from previous conversations. Hey Kivi can use semantic memory to retrieve context, answer questions, and prepare drafts. When the available history is insufficient or genuinely ambiguous, it should ask for clarification or say that it does not know.

Trust depends on control. People should be able to open a source from an answer, correct a mistaken memory, limit a preference to the right context, and remove information from future use. Those changes should survive restarts and reprocessing without requiring anyone to understand the underlying database.

Success means that Kivi can produce useful, source-backed answers from unfamiliar transcript history while remaining cautious about unsupported conclusions. The system should be measurable, inspectable, and clear about its limits. Always-on capture and autonomous external actions can wait until the memory experience itself is dependable.
